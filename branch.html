capítulo03

Branches são linhas paralelas de história, não cópias.

Uma branch no Git é só um ponteiro para um commit. Barato, leve e descartável — exatamente o que torna o trabalho em equipe possível.

03.2 — estratégias

Qual fluxo a equipe adota define a velocidade dela.

Não existe "melhor". Existe o que serve para o produto, o time e a frequência de deploy.

GitHub Flow

Uma branch principal. Branches curtas. Deploy contínuo.

Tudo o que entra na main está em produção. Cada feature é uma branch de poucos dias revisada por pull request. Funciona para SaaS e produtos web modernos.

Git Flow

Branches longas: develop, release, hotfix.

Estrutura rígida pensada para softwares com release planejado (mobile, desktop, on-premise). Mais cerimônia, mais controle, mais lentidão proposital.

03.3 — quando dá ruim

Conflito não é erro. É o Git pedindo sua opinião.

Quando duas pessoas mudam a mesma linha, o Git para e pergunta qual versão vale.

anatomia do conflito

1<<<<<<< HEAD
2const url = 'https://api.v1.com';
3=======
4const url = 'https://api.v2.com';
5>>>>>>> feature/api

como resolver

Edite o arquivo. Apague os marcadores. Commit.

Escolha uma das versões, as duas combinadas, ou algo novo. Depois:

resolução
$ git add src/config.js $ git commit -m "fix: padroniza endpoint v2"
